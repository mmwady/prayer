# رفيق المسجد — Mosque Companion

إضافة مستقلة إلى اقتدِ، دون تعديل تدريب الصلاة أو التحليل. الديمو يعمل فعليًا عبر Flutter → FastAPI → SQLite، ويحافظ على الحالة بعد تحديث الصفحة وإعادة تشغيل الخادم. لا يوجد نظام حسابات إنتاجي لهذه الميزة؛ تبديل الشخصيات مخوّل داخل جلسة تجريبية فقط.

## التشغيل

من جذر المشروع، افتح طرفيتين:

```powershell
.\backend\start_mosque_demo.ps1
```

```powershell
Set-Location mobile\coaching
flutter run -d chrome --dart-define=BACKEND_URL=http://127.0.0.1:8011
```

افتح بطاقة «رفيق المسجد — Mosque Companion» من الرئيسية. إذا كان التطبيق يحتفظ بعنوان خادم قديم، عدّله من درج إعدادات الخادم إلى `http://127.0.0.1:8011`. لا يحتاج الديمو مفاتيح مدفوعة.

للهاتف استخدم عنوان IP الجهاز المضيف ومنفذ 8011 في إعدادات الخادم، أو `http://10.0.2.2:8011` لمحاكي Android. GPS في المتصفح يحتاج localhost أو HTTPS. Android يطلب إذن foreground فقط؛ لا مشاركة خلفية. iOS/desktop لا يوجد لهما جسر GPS أو تشغيل خرائط في هذه الإضافة: الإدخال اليدوي يستمر، ويظهر خطأ واضح عند محاولة خدمة غير متاحة.

للوصول إلى الباك اند عبر الإنترنت: فعّل `MOSQUE_DEMO_ENABLED=true` في `backend/.env`، وأوقف الخادم الذي يستخدم المنفذ 8000، ثم شغّل `powershell -ExecutionPolicy Bypass -File backend/start_cloudflare.ps1` من جذر المشروع. ضع رابط HTTPS الناتج في إعداد عنوان الخادم بالتطبيق. بوابة النفق تسمح بمسارات الصلاة ورفيق المسجد وتمنع مسارات الإدارة؛ تستمر حماية جلسات الديمو. الرابط مؤقت، ويجب إبقاء السكربت والجهاز شغالين. النفق لا يستضيف واجهة Flutter Web.

البناء:

```powershell
flutter build web --no-pub --dart-define=BACKEND_URL=http://127.0.0.1:8011
flutter build apk --debug --no-pub --dart-define=BACKEND_URL=http://10.0.2.2:8011
```

## عرض 90–120 ثانية

1. أحمد U01 → «أحتاج رفيقًا» → منزل تجريبي (أو GPS بموافقة) → قباء → تفاصيل افتراضية → اعرض الرفقاء → يوسف → طلب الانضمام.
2. بدّل إلى يوسف U02 → «طلبات المرافقة» → قبول → أوافق. بدّل إلى أحمد → «رحلتي» → أؤكد العرض → أوافق.
3. بدّل إلى عمر U04 → «أحتاج رفيقًا». المستفيد محمود U03 بعلاقة مخولة. الإعداد الافتراضي: القبلتين، 11:55، توصيلة ودعم بسيط، عودة، لقاء بالمنزل.
4. اعرض الرفقاء → خالد وحده مؤهل: وجهة ولغة ومقعدان واعتماد ودعم وعودة؛ الانحراف محسوب على الشبكة المحاكية ≤ 8 دقائق. فهد ليس مؤهلًا بالوجهة والتوقيت، وناصر لا يملك اعتماد المساعدة.
5. أرسل طلب الانضمام → بدّل إلى خالد U05 → الطلبات → قبول والتزام بالعودة. عنوان محمود غير موجود في استجابة API قبل التأكيد.
6. عمر → رحلتي → تأكيد. اضغط بالتتابع «خرجت»، «وصلت نقطة اللقاء»، «بدأنا الرحلة»، «وصلنا للمسجد». يظهر أن العودة لم تُنجز؛ «بدأنا العودة» ثم «وصلنا وانتهت العودة» فقط يكملان الطلب.

الساعة ثابتة يوم الجمعة **2026-10-02 11:30 Asia/Riyadh**. الأوقات مواعيد رحلات خيالية، وليست الصلاة/الإقامة. أدوات اللجنة: تهيئة تدفق S03/S04/S06، تبديل الشخصية، تقدم 6 دقائق، تعطل عرض الطريق، وإعادة ضبط جلسة العرض. زر السيناريو يفتح طلبًا مُهيأ، ولا يتجاوز موافقات الأدوار. إعادة الضبط تعيد نفس seed والساعة دون حذف بيانات الصلاة.

## التغطية والاختبارات

`backend/tests/test_mosque_companion.py` يغطي S03–S10 وS12، المقعد الأخير باتصالين متزامنين، المنع الذاتي والتكرار والتعارض، خصوصية الاستجابات، منع تبديل الدور خارج الديمو، حفظ الموافقة على البيت، وفشل عرض الطريق S11. اختبارات Flutter تغطي تدفق الهاتف عند 320/390/820px، رفض GPS S02 واستمرار الإدخال اليدوي، المسجد الصحيح وعدم حفظ البيت تلقائيًا، المرشحين والانتظار وشاشة الرحلة المؤكدة. GPS الحقيقي يعتمد على الجهاز والإذن ولم يُستدل عليه من محاكاة الاختبار.

```powershell
Set-Location backend
.venv\Scripts\python.exe -m pytest -q
Set-Location ..\mobile\coaching
flutter analyze --no-pub
flutter test --no-pub
```

S05: طلب بلال وطلب أحمد كسيارة ولغة أردية 12:00 إلى قباء → دعوة سعيد لكليهما. قبول الأول يحجز المقعد مؤقتًا؛ الثاني يتلقى أن المقعد لم يعد متاحًا. الاختبار يكرر القبول في اتصالين SQLite مستقلين بالتزامن. S08: رفض كل الدعوات أو تقدم الساعة 12 دقيقة؛ القبول يحجز 5 دقائق فقط، فتقدم 6 دقائق يحرره. S09: سعيد يلغي الرحلة المنشورة مع سبب؛ بلال يرى الإلغاء ولا ينتقل آليًا إلى مرافق آخر. S07: ألغِ أي طلب قائم ثم جرب 15:00؛ تظهر حالة عدم المطابقة وخيار تعديل الطلب أو الانتظار. S10: طلب العودة يستبعد رحلة الذهاب فقط، دون تعديل صامت. لا يُكمل GPS أي رحلة آليًا.

## المتصل فعليًا والمحاكى

- **حقيقي:** HTTP إلى Backend، تخزين SQLite ومعاملات `BEGIN IMMEDIATE`، إسقاط الاستجابة بحسب الدور، GPS foreground في Android وWeb بعد الموافقة، وفتح Google Maps خارجيًا إذا توفر. لا ننقل GPS للنموذج.
- **محاكاة معلنة:** الشخصيات والبيوت والاعتماد والساعة وأزمنة الطرق واللقاء. مزود التوجيه شبكة مستقيمة الزوايا خيالية، لا طرق المدينة الفعلية. يقارن نفس المزود `driver→meeting→destination` بـ `driver→destination` وبنفس السرعة، وليس المسافة المباشرة. كل المسافات المباشرة موسومة منفصلة. عند تعطّل عرض المسار تظهر النقاط والمسافة المباشرة فقط؛ المطابقة تستمر بمزود الديمو المعلن.
- **الإشعارات:** صندوق تحديثات محفوظ داخل الديمو فقط، لا push/SMS/email ولا أشخاص حقيقيون.
- **AI:** غير متصل بميزة الرفيق. الإعدادات المنظمة ومراجعة المستخدم هي الأساس؛ الشرح قوالب مشتقة من بيانات الأهلية والحسابات. خدمة DeepSeek الموجودة لتوجيه الصلاة منفصلة؛ لا تستقبل هذه البيانات ولا يلزم نجاحها لتأكيد الرحلة.
- **لا مشاركة موقع حي:** لم يُضف زر يوحي بها. تقدم الرحلة يدوي مؤكد.

## إعدادات وحدود الإنتاج

الإعدادات في `backend/app/config.py` وعبر `backend/.env`، دون أسرار في Flutter:

```dotenv
MOSQUE_DEMO_ENABLED=false
MOSQUE_DEMO_DB=data/mosque_companion.sqlite3
MOSQUE_HOLD_MINUTES=5
MOSQUE_INVITATION_MINUTES=10
MOSQUE_INVITATION_BATCH=3
```

`BACKEND_URL` متغير بناء Flutter أو إعداد الخادم المحلي الموجود. أوزان وحدود المطابقة وسرعات المحاكاة مركزية في `MatchConfig`؛ يمكن حقن بديل دون تغيير الشاشات. واجهات `Clock`, `MosqueProvider`, `RouteProvider`, `Notifications`, وFlutter `LocationService` قابلة للاستبدال؛ لا توجد مفاتيح خرائط مطلوبة للديمو. تشغيل خرائط/توجيه حقيقي يتطلب تنفيذ مزود وتهيئة سرية على الخادم، وليس مجرد إضافة مفتاح غير مستخدم.

مصادقة الإنتاج وإدارة الاعتماد والعلاقات الأسرية، تشفير بيانات حساسة، إدارة احتفاظ/حذف الجلسات، مزود طرق فعلي ومداخل ونقاط التقاط معتمدة، وإشعارات بين أجهزة إنتاجية **غير منفذة**. لا نسمح بتحويل جلسة الديمو لحساب حقيقي. bearer عشوائي يُحفظ في SharedPreferences، والخادم يخزن hash له؛ لكل جلسة بيانات معزولة. تبديل الدور يقبل شخصيات seed فقط ومع `MOSQUE_DEMO_ENABLED=true`. إيقافه يغلق جميع إجراءات الميزة بـ503؛ حالة config فقط متاحة.

SQLite يثبت ذرية السعة عبر اتصالات محلية إلى الملف نفسه، لكنه ليس اعتمادًا على بنية موزعة أو مصادقة مستخدمين حقيقيين. لا تُسجل إحداثيات المنازل في السجلات. الصفحة تُحدّث بعد الأفعال/تبديل الشخصية أو زر تحديث، دون socket/push أو استطلاع حي تلقائي. الوقت يتقدم يدويًا في الديمو فقط؛ يجب استبدال الساعة بالوقت الفعلي عند تنفيذ مسار الإنتاج.
